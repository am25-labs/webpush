## Project Overview

Web Push notification microservice built with Express 5, TypeScript, and the `web-push` library. Works as both a standalone CLI server and an importable library. Uses ES modules (`"type": "module"`). Package manager is pnpm.

## Commands

- **Install dependencies:** `pnpm install`
- **Build:** `pnpm build` (compiles TypeScript to `dist/`)
- **Watch mode:** `pnpm dev`
- **Start server:** `pnpm start` (runs compiled `dist/bin/webpush.js`, default port 5500)
- **Generate VAPID keys:** `pnpm run generate:vapid`

No test framework or linter is configured.

## Architecture

```
src/router.ts    ← Core: createPushRouter(webpush) returns Express Router with endpoints
src/server.ts    ← Standalone server: dotenv, VAPID config, cors, body parsing, app.listen
src/vapid.ts     ← CLI script to generate VAPID key pairs
bin/webpush.ts   ← CLI entry point (shebang + imports src/server.js)
index.ts         ← Library entry point: exports createPushServer(), createPushRouter(), and types
dist/            ← Compiled JS output (gitignored, generated by pnpm build)
```

**Two usage modes:**

1. **CLI** (`npx am-webpush` or `pnpm start`): `bin/webpush.ts` → `src/server.ts` → `src/router.ts`. Reads VAPID config from `.env`.

2. **Programmatic**: `import { createPushServer } from 'am-webpush'` returns an Express Router. Caller provides VAPID config as arguments and mounts the router in their own Express app. Caller must apply `express.json()` middleware before mounting.

**Exported types:** `PushSubscription`, `PushPayload`, `PushServerOptions`

**Endpoints** (in `src/router.ts`):
- `GET /health` — health check
- `POST /send` — push notification to a single subscription
- `POST /send-many` — push notification to multiple subscriptions (parallel via `Promise.all`)

## Environment

Requires a `.env` file with `VAPID_SUBJECT`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` (only for CLI mode, not committed).
