# Self-hosting from source

This guide is for developers who want to run the server directly from source, contribute to the project, or deploy via a platform that builds from a Git repository (e.g. Dokploy, Railway, Render).

For the standard setup, see the [README](README.md).

Important: this guide is for the Git repository mode, not the published npm package mode.

- Published package mode: install `@am25/webpush` into another app and run `webpush`.
- Git repository mode: clone this repository, build it, and run the compiled server from `dist/`.

---

## Requirements

- Node.js >= 18
- pnpm

---

## Setup

### 1. Clone the repository

```bash
git clone https://github.com/am25-labs/webpush.git
cd webpush
```

### 2. Install dependencies

```bash
pnpm install
```

### 3. Configure environment variables

Copy the example file and fill in your values:

```bash
cp .env.example .env
```

```env
VAPID_SUBJECT=mailto:you@example.com
VAPID_PUBLIC_KEY=your_vapid_public_key_here
VAPID_PRIVATE_KEY=your_vapid_private_key_here
API_KEY=your_api_key_here
PORT=5500
```

Generate a VAPID key pair if you don't have one:

```bash
pnpm run generate:vapid
```

### 4. Build

```bash
pnpm build
```

### 5. Start the server

```bash
pnpm start
```

The server will be available at `http://localhost:5500`.

For Dokploy or similar platforms, use:

- Install command: `pnpm install`
- Build command: `pnpm build`
- Start command: `pnpm start`

## Development

```bash
pnpm dev    # Watch mode — recompiles on every change
```

## Project structure

```
src/
  router.ts    ← Express Router with all endpoints and API key middleware
  server.ts    ← Standalone server: dotenv, VAPID config, cors, body parsing, listen
  vapid.ts     ← Script to generate VAPID key pairs
index.ts       ← Library entry: exports createPushRouter() and types
bin/
  webpush.ts   ← CLI entry point (imports src/server.ts)
  create.ts    ← Setup wizard (used by npx)
dist/          ← Compiled output (generated by pnpm build, not committed)
```
